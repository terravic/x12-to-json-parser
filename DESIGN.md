# Dashboard Design Specification

This document defines the visual, structural, and technical specifications for standalone interactive HTML dashboards (`dashboard.html`) generated by the X12-to-JSON Healthcare Parser.

---

## 1. Visual Hierarchy and Typography

| Design Dimension | Specification | Implementation Standard |
|---|---|---|
| **Typography** | Distinct typographic hierarchy across prose, headings, and tabular values. | Pair a sans-serif UI font (`DM Sans` or `Geist Sans`), a serif display font (`Instrument Serif`), and a tabular monospaced font (`Geist Mono`). |
| **Surfaces and Depth** | Flat, solid surface tokens with clear structural boundaries. | Use solid background tokens and `1px solid` borders (`6px` to `8px` radius) for separation rather than multi-stop color gradients. |
| **Container Layout** | Single-level bento-style grid organization. | Partition panes using flat grid cells and thin `1px` dividers rather than nested card-in-card containers. |
| **Status Indicators** | High-signal state reporting. | Highlight warning, error, or pended states explicitly; render nominal items using monospaced or muted tokens. |
| **Background Surfaces** | Uncluttered viewport backgrounds for node maps and workspaces. | Reserve gridlines strictly for quantitative chart axes and coordinate plots. |
| **Control Surfaces** | Text-based section headers and segmented action controls. | Use typographic hierarchy for pane titles, tab labels, and interactive segmented controls. |

---

## 2. Runtime Environment and Technical Architecture

* **Self-Contained Execution:** Dashboards execute in standard web browsers and sandboxed webviews using standard HTML5, CSS custom properties, and JavaScript without external CDN dependencies.
* **Dynamic State Updates:** UI components support incremental state updates, dataset switching, custom stream parsing, and live HTTP Server-Sent Events (SSE) refresh without resetting scroll position or active camera state.
* **Standalone Output (`dashboard.html`):** Build workflows emit a self-contained `dashboard.html` file at the project root (and transaction-specific files under `docs/`) that can be opened directly from local storage or served over HTTP.
* **Empirical Data Rendering:** All views render computed transaction payloads, provenance digests, and telemetry metrics from the active stream.

---

## 3. Light, Dark, and System Theme Specifications

The dashboard supports a light mode, a high-contrast dark mode, and an automatic system mode that tracks operating system appearance preferences.

* **Segmented Theme Selector:** The theme switcher in the top navigation bar is a compact segmented control consisting of three text-labeled buttons placed side by side:
  * **Light Mode (`#theme-btn-light`):** Text label `Light` (`title="Light Theme"`, `aria-label="Light Theme"`, `data-theme-mode="light"`).
  * **Dark Mode (`#theme-btn-dark`):** Text label `Dark` (`title="Dark Theme"`, `aria-label="Dark Theme"`, `data-theme-mode="dark"`).
  * **System Mode (`#theme-btn-system`):** Text label `System` (`title="System Theme"`, `aria-label="System Theme"`, `data-theme-mode="system"`).
  * Each button marks the active mode via the `active` class and `aria-pressed="true"`, persisting the selected mode (`light`, `dark`, or `system`) in `localStorage`.
* **System Theme Detection:**
  * **Browser Layer:** When `system` mode is selected, the active theme is resolved via `window.matchMedia('(prefers-color-scheme: dark)')` with a real-time `'change'` event listener.
  * **Host Backend Fallback:** When generated by the Python CLI or HTTP server, desktop environment color-scheme preferences (such as `GTK_THEME`, `gsettings` `color-scheme`, or `~/.config/kdeglobals`) are queried to populate `system_theme` in the embedded bundle as a fallback for headless webviews.
* **Color Schemes:**
  * **Light Mode:**
    * Background: `#FAFAF9`
    * Cards and Surfaces: `#FFFFFF`
    * Borders: `#E7E5E4` (`1px solid`, `6px` to `8px` border-radius)
    * Text Primary: `#1C1917`
    * Text Secondary: `#787774`
  * **Dark Mode:**
    * Background: `#0D0E11`
    * Cards and Surfaces: `#16171D`
    * Borders: `#292A30` (`1px solid`, `6px` to `8px` border-radius)
    * Text Primary: `#ECE8E2`
    * Text Secondary: `#9A9895`

## 4. Dashboard Layout and Component Specifications

* **Section Headings:** Component headers state the analytical domain and active transaction source directly.
* **Tables:** Numerical and tabular cells use the monospaced font stack (`Geist Mono`) with `font-variant-numeric: tabular-nums` and `1px` horizontal row dividers.
* **3D and Network Visualizations:**
  * Interactive 3D molecular and spatial loop conformer views use deterministic 3D perspective projection (`Software Projection Fallback`) supporting orbit, zoom, and coordinate inspection across all browser environments.
  * Core studio components use the domain titles `Interactive Relationship Node Map` and `Structural Data Diagram`.
  * Layout and link geometry calculations remain deterministic to preserve pan and zoom responsiveness.

## 5. Dynamic Data Visualization and Color Palette

Container surfaces remain neutral while quantitative charts, concentration matrices, directed graphs, and 3D conformer views apply a five-color semantic palette:

### Data Visualization Color Palette

| Color Role | Hex Code | Visual Application |
|---|---|---|
| **Vibrant Teal** | `#0D9488` | Primary data series, baseline metrics, structural bonds, nominal nodes. |
| **Energetic Amber** | `#D97706` | Secondary data series, adjustments, latency overlays, intermediate thresholds. |
| **Vivid Indigo** | `#4F46E5` | Comparison series, active selections, entity and clinical nodes. |
| **Functional Emerald** | `#059669` | Validated states, adjudicated payments, verified coverage. |
| **Deep Rose** | `#E11D48` | Pended holds, severe allergy alerts, peak density strata. |

### Visualization Rules

* **Matrices and Heatmaps:** Interpolate cell fills from the active surface background through **Vibrant Teal** (`#0D9488`) and **Vivid Indigo** (`#4F46E5`) to **Deep Rose** (`#E11D48`).
* **Network and Molecular Graphs:** Color nodes by category or validation state using the semantic palette above, with semi-transparent link strokes derived from connected node states.
* **Chart Backgrounds and Gridlines:** Keep chart plot backgrounds transparent to inherit the active surface color, and render horizontal axis gridlines using `#E7E5E4` in light mode and `#292A30` in dark mode.

---

## 6. Acceptance Criteria

1. Build generation outputs a standalone `dashboard.html` bundle capable of local execution and live HTTP SSE synchronization.
2. The segmented theme control (`Light`, `Dark`, `System`) applies exact Light Mode and Dark Mode hex tokens and tracks OS color-scheme updates.
3. Quantitative 2D charts, concentration heatmaps, directed relationship node maps, and 3D structural diagrams render active stream data using the five-color semantic palette and re-render immediately upon dataset selection, file upload, or theme change.
4. All seven dashboard tabs (`Workspace Studio`, `Interactive X12 & JSON Explorer`, `Transaction & Provenance`, `C-CDA Clinical Payload`, `Raw X12 File`, `Structured JSON`, `Field Mapping Spec`) reflect the currently selected or uploaded transaction stream.
